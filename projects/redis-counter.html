Building a multi-container counter application

A Docker Compose stack combining NGINX, multiple web containers and Redis-backed shared state.

Completed learning projectDockerComposeNGINXRedisFlask
View repository ↗Contact
01 — Challenge

The problem.

The project needed multiple application containers to serve traffic while keeping a shared visitor count consistent across instances.

Architecture
ClientNGINXWeb ×3Redis
02 — Implementation

How it was built.

  1. 01Containerised the web application and Redis service.
  2. 02Added NGINX as the entry point and reverse proxy for the web service.
  3. 03Scaled the web service to three containers to demonstrate horizontal distribution.
  4. 04Used Redis as shared state so the counter was not tied to one application container.
  5. 05Exposed the application through port 5050 and tested the counter endpoint.
docker · nginx · redis
▋
03 — Troubleshooting

What required judgement.

  • Ensuring service names and ports were correct inside the Compose network.
  • Understanding why application state cannot live inside one scaled web container.
  • Routing traffic through NGINX while keeping the application containers interchangeable.
04 — Result

What worked.

Requests could be distributed through NGINX while all web containers used the same Redis-backed counter state.

05 — Production considerations

What I would change next.

These are improvements I would make for a production-grade implementation; they are not presented as already completed.

  • Add explicit health checks and restart policies.
  • Secure Redis and avoid exposing it outside the application network.
  • Add TLS at the edge.
  • Add metrics/log collection and service dashboards.
  • Move to an orchestrator when availability and scaling requirements justify it.
