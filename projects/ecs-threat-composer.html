Deploying a containerised application on AWS using Terraform

Built, containerised and deployed an application using Docker, Terraform and ECS, with HTTPS and a custom domain.

Completed projectDockerECRECS FargateALBRoute 53ACMGitHub Actions
View repository ↗View live application ↗
01 — Challenge

What I was trying to achieve.

I wanted to take a web application from local containerisation through to a repeatable AWS deployment. The project needed to package the application with Docker, store images in ECR, run the workload on ECS Fargate, expose it securely through an Application Load Balancer and custom domain, and move the infrastructure from manual setup into modular Terraform and CI/CD.

Request path
Route 53ALB / HTTPSECS Fargate

ECS tasks run the NGINX-served application image pulled from ECR. ACM provides the certificate used by the load balancer.

02 — Implementation

How it was built.

  1. 01Built the application with a multi-stage Dockerfile and used NGINX as the runtime web server, including a /health endpoint.
  2. 02Validated the container locally before pushing the application image to Amazon ECR.
  3. 03Created the initial ECS cluster, Fargate service, load balancer, target group, security groups, Route 53 DNS and ACM certificate manually to understand how the services worked together.
  4. 04Removed the manual resources and rebuilt the networking, security, ECR, ACM, ALB and ECS infrastructure using modular Terraform with remote state in S3.
  5. 05Added GitHub Actions workflows using OIDC for infrastructure changes and application deployments without stored long-lived AWS access keys.
  6. 06Configured HTTP-to-HTTPS redirection and restricted inbound application traffic so ECS tasks are reached through the load balancer.
  7. 07Verified the live deployment through https://tm.nabilstack.com/health.

03 — Troubleshooting

What required judgement.

  • Running NGINX as a non-root user caused a PID permission issue, resolved by moving the PID file to /tmp.
  • ACM validation was delayed by Route 53 hosted-zone issues, requiring DNS and certificate validation troubleshooting.
  • ARM64 builds in GitHub Actions were initially slow under emulation, so the build process was adjusted to keep the build stage native while producing the required runtime image.
  • A Yarn network timeout in CI required increasing the network timeout rather than treating the pipeline failure as an application issue.
04 — Outcome

What worked.

The application is deployed on ECS Fargate behind an HTTPS Application Load Balancer and custom Route 53 domain. Docker images are stored in ECR, infrastructure is managed with modular Terraform, and GitHub Actions uses OIDC for both infrastructure and application deployment workflows.

05 — Production considerations

What I would improve next.

These are improvements I would make for a more production-oriented implementation; they are not presented as already completed.

  • Run ECS tasks in private subnets and use private networking for workload egress where appropriate.
  • Add ECS service autoscaling based on workload metrics.
  • Add container-image vulnerability scanning and stronger image promotion controls.
  • Add CloudWatch alarms and application-level observability beyond log collection.
  • Introduce staged environments and deployment approvals before production changes.
